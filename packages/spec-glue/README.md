# @computerwwwizards/spec-glue

`spec-glue` binds implementation handlers to Markdown-declared spec steps. Write your scenarios and steps as plain Markdown (a `## Scenarios` section with `### <title>` headings and bullet-point steps), then register `Step(pattern, handler)` bindings that get pattern-matched — including `{variable}` extraction — against each step when the scenario runs.

## Installation

```sh
npm install @computerwwwizards/spec-glue
```

## Examples

Given a Markdown spec:

```md
## Scenarios

### Signing in with valid credentials

- Given a registered user "{email}"
- When they sign in with the correct password
- Then they should see their dashboard
```

Bind and run it:

```ts
import createFeature from '@computerwwwizards/spec-glue';

const feature = createFeature(markdownContent, (Scenario) => {
  Scenario('Signing in with valid credentials', (Step) => {
    Step('Given a registered user "{email}"', (variables, ctx) => {
      ctx.store.register('email', variables.email);
    });

    Step('When they sign in with the correct password', async (_variables, ctx) => {
      const email = ctx.store.get<string>('email');
      // ...perform the sign-in for `email`
    });

    Step('Then they should see their dashboard', () => {
      // ...assert the dashboard is visible
    });
  });
});

for (const scenario of feature.scenarios.values()) {
  await scenario.run();
}
```

Each scenario carries its own `store` (a simple key/value map) so steps within the same run can share state, and `Step` patterns support `{name}` placeholders that are extracted into the `variables` argument passed to the handler.

## Troubleshooting

- **`Error: Step not registered: ...`** — a step in the Markdown has no matching `Step(pattern, handler)` binding. Either register a handler with a matching pattern, or call `scenario.configure({ omitNonRegisteredSteps: true })` to skip unregistered steps instead of throwing.
- **Step pattern not matching** — patterns are matched case-insensitively and tolerate trailing punctuation, but literal regex special characters in your pattern text are escaped automatically; only `{variableName}` placeholders are treated specially.
